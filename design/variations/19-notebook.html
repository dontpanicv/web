Beyond the Tool-Calling Loop: How We Built an AI Analyst with Bash, a Mounted Filesystem, and a JSON Renderer

2026-04-29 · excerpt

Most AI features built today follow the same recipe: take the Vercel AI SDK, register a handful of tools, write a system prompt, and stream the result into a markdown component. It works. It is also where most teams stop — and where most AI products start to feel limited.

That recipe is fine for operational assistants. The conversation is short, each tool returns a small, well-shaped object, and the markdown is the answer. It stops working the moment the model needs to think with data.

The first wall is large tool output. Whatever a tool returns goes straight into the model’s context. A query that returns 50k rows is now 50k rows of JSON sitting in the conversation, on every subsequent turn, paid for in tokens, and pushing earlier reasoning out of the window. You can paginate, truncate or summarize, but these are coping mechanisms: they either lose information or force the model to make decisions about data it cannot see.

The second wall is subtler and arrives earlier. To answer almost any analytical question the model needs to know what exists, and the naive way to expose that is one inventory tool per kind of thing. The model, being agreeable, calls all of them “to orient itself”. Tens of thousands of tokens of metadata sit in context before the question is even processed — and there is no grep.

So instead of a dozen inventory tools, we give the model one tool — bash — and a filesystem with the inventory already written to disk:

const workspace = new Bash();
await workspace.writeFile('/context/inventory.json', JSON.stringify(inventory));

Two more ideas complete it: a SQL execution layer that mounts query results as files, so bulk data is sliced and counted rather than read; and a JSON renderer with a predefined component manifest, so the answer arrives as a rendered analysis instead of prose about one.

Your AI doesn’t need more tools. It needs fewer tools and a filesystem. Possibly also therapy, but we’re starting with the filesystem.
